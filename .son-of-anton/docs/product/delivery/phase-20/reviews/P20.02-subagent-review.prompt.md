### Diff context

[+ `record-deferred` subcommand], `reconcile-subagent-refactor-review`) to `cli-runner.ts`,

and ticket-state fields introduced in ticket 20.01 (`refactor-review.ts`).

Key changes:
- `tools/delivery/subagent-runner.ts`: adds `runProgrammaticSubagentReview`, a new, purely-additive,
  dependency-injected function that reuses the existing generic primitives
  (`runSubagentWithFallback`, `tryRunner`, `buildRunnerSpawnCommand`, `decideAdvisoryRunnerOutcome`)
  to orchestrate a runner invocation without duplicating their internals. No existing exports were
  modified.
- `tools/delivery/refactor-review.ts`: adds path/suffix derivation functions, prompt-validity check
  (`isValidRefactorReviewPromptContent`), prompt-writing (`writeRefactorReviewPrompt`), and ticket-state
  recording (`recordRefactorReviewOutcome`) — the latter updates only the P20.01 `refactorReview*`
  fields, deliberately not touching `TicketState.status`.
- `tools/delivery/cli-runner.ts`: adds the three new case blocks plus supporting helpers
  (`resolveRefactorReviewPromptContent`, `loadRefactorReconciliationContext`,
  `runRefactorReconciliationGate`). Widens `resolveInternalReviewPatchCommits`'s suffix parameter type
  from a 2-value union to a 3-value union (adding `'[refactor-review]'`) — purely additive to the type,
  no behavior change for existing callers passing the original two values.
- No gate placement: these commands are not yet required before `open-pr` and do not block anything in
  the existing pipeline. That wiring is ticket 20.03's explicit scope.

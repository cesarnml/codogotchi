**F1 — Missing state.json seed fallback in seedRpgState**
File: `packages/cli/src/hook-binary.ts`, function `seedRpgState` (lines 1056–1103)
What is wrong: The ticket Outcome and Green sections both specify that when no v7 slices exist in `state.d/`, `rpg-state.json` should be seeded from `state.json` (which could contain v7 RPG fields from a prior write). `seedRpgState` returns `null` instead, causing the caller to use freshly computed v5 defaults. Fix: After the `readdir` loop returns `null` (or catches a readdir error), attempt to read `join(home, "state.json")`, parse it, and if it carries `level` and `half_hearts` as numbers, return a seeded `RpgStateJson` from those fields. **Advisory Observations**

The SIGKILL window between `writeSliceAtomic` and `writeRpgStateAtomic` has a narrower blast radius than the spec describes for the migration case. Specifically: if the hook's `session_id` matches the `session_id` of the only v7 slice on disk, `writeSliceAtomic` overwrites that v7 slice with a v8 slice before the rpg-state write. A subsequent SIGKILL leaves `seedRpgState` unable to find any v7 data on the next invocation, and migration seed data is permanently lost for that user. The spec-acknowledged "slice-before-rpg window" (Attack Surface 2) does not call out this overwrite interaction. Worth a comment in `runHook` noting that the v7 → v8 slice overwrite is the point of no return for seed data.

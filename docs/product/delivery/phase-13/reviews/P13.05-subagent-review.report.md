**Actionable findings**

- `apps/menubar/Sources/FloatingPetWindowPool.swift:87` to `apps/menubar/Sources/FloatingPetWindowPool.swift:146` — changing an existing origin from `own` to `combined` does not collapse its old own window on the next tick. Step 5 only dismisses windows that are stale by TTL, then Step 8 spawns/updates `"combined"`, leaving the previous origin-keyed window visible until TTL expiry. This breaks the ticket outcome: “Setting an origin to `combined` on the next tick collapses its window into the shared window.” Fix: after reading customization and computing routing, dismiss any existing own-key window whose current `windowKey(for:)` is now `"combined"` before or during the spawn/update phase.

- `apps/menubar/Sources/FloatingPetWindowPool.swift:57` to `apps/menubar/Sources/FloatingPetWindowPool.swift:96` — changing a live origin to `off` does not reliably remove it from the render pipeline on the next tick. The origin is filtered out of `visibleEntries`, but its previous window can survive TTL cleanup, especially when it is still `lastActiveWindowKey`; with no other visible origin it can remain indefinitely. This breaks the ticket outcome: “Setting an origin to `off` on the next tick removes it from the render pipeline.” Fix: explicitly dismiss existing windows for origins whose current mode is `.off` before applying last-active TTL immunity.

- `apps/menubar/Sources/CustomizationJsonReader.swift:45` to `apps/menubar/Sources/CustomizationJsonReader.swift:48` and `apps/menubar/Sources/FloatingPetWindowPool.swift:52` to `apps/menubar/Sources/FloatingPetWindowPool.swift:54` — negative `idle_dismiss_ttl_seconds` is accepted by the Swift reader and becomes a negative `TimeInterval`, causing non-last-active visible windows to be treated as immediately stale on every tick. This is a correctness gap at the module boundary; the P13.02 contract says the field is non-negative, but this Swift consumer does not enforce it. Fix: reject or normalize negative TTL in `CustomizationJsonReader` before constructing `CustomizationSnapshot`, preferably by returning `.safeDefault` for schema-invalid values or clamping to `300`.

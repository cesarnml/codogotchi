**Actionable findings**

- `apps/menubar/Sources/CustomizationTabViewModel.swift:77` to `apps/menubar/Sources/CustomizationTabViewModel.swift:94` — `persist()` treats any existing-file read or parse failure as an empty payload, then writes the managed keys back with `.atomic`. This breaks invariant 2 because an unreadable or temporarily unparsable existing `customization.json` can be replaced without preserving unmanaged keys such as `menubar_icon_monochrome` or future fields. Fix: if the file exists but cannot be read or parsed as a JSON object, abort the write and surface/log the failure instead of starting from `{}`; only start from `{}` for a confirmed absent file.

- `apps/menubar/Sources/CustomizationTabViewModel.swift:77` to `apps/menubar/Sources/CustomizationTabViewModel.swift:89` — when Settings creates `customization.json` from an absent file, it never writes `schema_version: 1`, so the resulting file fails the established contract in `packages/contracts/src/customization.ts:5` to `packages/contracts/src/customization.ts:11`.

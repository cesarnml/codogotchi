### Diff context

`DesiredWindow.modeIndicatorBadge: String?` (new field, `DesiredWindows.swift`) is computed in `PoolDerive.swift` immediately after the existing `foldedSessionDisplay` computation, gated on the same `key != resolvedIdentity` condition:
```swift
if key != resolvedIdentity {
    window.modeIndicatorBadge = key == .combined ? "Combined" : PlatformAttribution(origin: key.origin)?.displayName
}
```
`PoolApply.push` calls `controller.applyModeIndicatorBadge(window.modeIndicatorBadge)` right after `applyFoldedSessionDisplay`. The new protocol member `applyModeIndicatorBadge(_ text: String?)` is added to both `FloatingPetWindowControlling` and `PanelManaging`, each with a default no-op extension mirroring `applyFoldedSessionDisplay`'s exact placement.

Rendering: `AnimationBadgeView` (shared by `MinimalistBadgeView` and Own mode's `AnimationBadgePanel`) gained a `modeIndicatorLabel: NSTextField` (small, secondary-color, non-interactive) and a `configureModeIndicator(_ text: String?)` method — kept separate from `configure()` so it isn't clobbered by an unrelated same-tick redraw, mirroring `configurePromptTimer`. `preferredSize` was extended to account for the new label's size.

`MinimalistBadgeView.applyModeIndicatorBadge` forwards directly to `animationBadge.configureModeIndicator(text)`; `renderedModeIndicatorBadge` (test-observable) reads `animationBadge.currentModeIndicatorText`.

`FloatingPetPanelController` stores `currentModeIndicatorBadge: String?`, guards on change, and calls `repositionAndShowAnimationBadge()`. That value is threaded through 3 call sites into `ChromeFlockCoordinator.repositionAnimationBadge`/`liveRepositionAnimationBadge` → `AnimationBadgePanel.reposition(modeIndicator:)` → `badgeView.configureModeIndicator(modeIndicator)`.

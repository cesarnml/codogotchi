**Actionable findings**

- `apps/menubar/Sources/Pool/Derive/PoolDerive.swift:385,427` — `resolvedIdentity` is initialized to the display key before winner resolution. For a folded plain-origin snapshot with no `renderKeyIdentities` entry, that display origin is treated as a real default session: `hasActiveSession` becomes true and prune targets `<origin>.json`. This violates invariant 2’s missing-identity no-op requirement and can delete an unrelated default slice. Represent resolution as optional or carry an explicit `hasResolvedIdentity`; only fall back to `winnerEntry.key` when it is genuinely session-keyed.

- `apps/menubar/Sources/Pool/Derive/PoolDerive.swift:382-385,427` — transient Combined retention begins from `previousCombinedWindow` but immediately overwrites its resolved winner with `.combined`. With no current `winnerEntry`, the retained live window loses Sync Label/Prune capability and prune becomes a no-op despite representing the previously retained real session. Preserve the prior resolved identity/capability for the intentional one-tick retention, or explicitly decide that the retained window has no current identity and remove it rather than presenting stale session state. Add a two-tick Combined regression test.

- `apps/menubar/Sources/Pool/FloatingPetWindowPool.swift:442` and `apps/menubar/Sources/Pool/Derive/PoolMemoryUserActions.swift:85` — widened prune passes the display key into `memory.pruning`. A Combined prune therefore records `"combined"` in `prunedOrigins`, not the resolved winner’s origin; folded keys happen to work only because their display origin matches. This defeats the documented post-prune promotion restriction if that resolved origin later enters a capped session mode. Make pruning accept the resolved origin separately and arm `prunedOrigins` with that origin while retaining the display key for window teardown.

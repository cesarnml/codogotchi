### Ticket scope

**Outcome:**
- The macOS renderer checks `attention.expires_at` on every `state.json` read.
- If `attention.expires_at < now`, the renderer treats `activity_state` as `idle` regardless of the written value — "stuck waving" is resolved.

- The TTL check applies in both lite and alive modes.
- The pet decays to `idle` pose when TTL expires — no bubble shown, no `standby` animation held.

**Rationale notes:**
- TTL check is applied at read time (inside `StateJsonReader.read(at:)`) — no background timer, no extra write.

- `AttentionPayload.expiresAt` is `String?` (optional) so a missing `expires_at` field does not cause parse failure — it falls through to `activity_state` as-is.
- `resolveActivityState` is applied to ALL activity states, but for non-expired or absent TTL it is a transparent pass-through.
- Polling window: `LivePollingDriver` polls every 1 second; up to ~1 second latency after expiry is acceptable for Phase 06.

### Attack surfaces to probe

1. **`resolveActivityState` boundary condition** — the guard chain uses `expiry < now` (strict less-than). A timestamp equal to `now` (exact boundary) is NOT treated as expired — the raw state passes through. Verify this is the intended semantics and does not allow an edge-case where an exact-boundary TTL is observed as `standby` indefinitely.

2. **`parseISO8601Date` format coverage** — does the two-pass formatter handle the three plausible `expires_at` shapes produced by the hook: `"2026-05-29T14:00:00.000Z"` (fractional + Z), `"2026-05-29T14:00:00Z"` (no fractional + Z), and `"2026-05-29T14:00:00+00:00"` (offset form)? Verify the second pass does not silently reject the `+00:00` offset.

3. **`AttentionPayload` partial decode robustness** — `expiresAt` is `String?`. Probe: (a) `"attention": {}` (no `expires_at`) — does `JSONDecoder` succeed and leave `expiresAt` nil? (b) `"attention": {"expires_at": null}` — does JSON null decode to `nil` without throwing? (c) `"attention": {"expires_at": 42}` (wrong type) — does this correctly produce `.malformed`?

4. **`StateSnapshot` field preservation through TTL resolution** — the implementation builds a `raw` snapshot, applies `resolveActivityState`, then builds a second `StateSnapshot` substituting only `activityState`. Verify that `schemaVersion`, `updatedAt`, `sourceEvent`, and `attention` are copied faithfully and that `attention` is not stripped from the returned snapshot (callers may need it).

5. **`LivePollingDriver` transition log integration** — `runTick` calls `reader(pollingTargetPath)` and records `snapshot.activityState` as `lastAgentState`. Since TTL is applied at read time, a transition from `standby` to `idle` triggered purely by TTL expiry (with no hook write) will be recorded in the transition log. Verify this doesn't produce a phantom `prev=standby → idle` entry on every read cycle once TTL expires (the dedup guard `if prev != snapshot.activityState` should prevent it after the first cycle).

6. **`resolveActivityState` access level** — it is declared `static func` with default (internal) access. Verify the test file can call it via `@testable import` and that no tests depend on it being public.

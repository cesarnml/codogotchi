**Actionable findings**

**Finding 1 — `hooks.ts:511–529` — `uninstallCursorHooks` creates `~/.cursor/hooks.json` when it did not exist (Surface 2 / spec-permits-real-bug)**
The spec-permitted invariant ("succeed without error") allows this, but the behavior is a real user surprise: an uninstall that has nothing to remove creates a file. The fix is a short-circuit at the top of `uninstallCursorHooks`:
```ts
const cursorPath = join(root, CURSOR_HOOKS_REL);
if (!(await fileExists(cursorPath))) return;
```
This keeps the function a true no-op on absent files and avoids creating an unexpected empty hooks file.

**Finding 2 — `hooks.ts:567` — `cursorBridgeInstalled` condition breaks Invariant 3 (Surface 3 / invariant-breaking)**
```ts
// current (broken):
const cursorBridgeInstalled = !cursorNativeInstalled && claudeCodeInstalled;
// fix:
const cursorBridgeInstalled = !cursorNativePresent && claudeCodeInstalled;
```
`cursorNativePresent` is already computed two lines above. If the cursor file exists with non-Codogotchi entries, `cursorNativeInstalled = false` but `cursorNativePresent = true`; the current code incorrectly returns `source_origin: "bridge"` for that state. The invariant says bridge requires "no native cursor file exists."

**Finding 3 — `hooks.ts:127–129` — `readJsonOrEmpty` admits JSON arrays, silently discards cursor hook writes (Diff-derived Surface 4 / spec-permits-real-bug)**
`typeof [] === "object"` passes the guard. When `~/.cursor/hooks.json` contains `[]`, `installCursorHooks` adds string-keyed properties to the array and `JSON.stringify` drops them, writing `[]` back. All 5 hook installs are silently lost. Fix: reject arrays in the guard:
```ts
if (parsed && typeof parsed === "object" && !Array.isArray(parsed))
  return parsed as T;
```
This causes `readJsonOrEmpty` to fall through to `return {} as T`, treating a corrupt-but-valid JSON array as empty, and the install proceeds correctly.

**Advisory Observations**

- **`source_origin` not surfaced in plain-text `hooks status` output (`router.ts:519–525`):** The text formatter emits `${name}: ${installed}, ${installable}` only. A user running `codogotchi hooks status` (the natural default) sees no indication of `native` vs `bridge` mode for Cursor, which is the key behavioral distinction the ticket's README section documents. Only `--json` exposes `source_origin`. The README documents both modes as meaningful to users, so it would be worth adding `source_origin` to the text row when it is non-`undefined` (e.g., `cursor: installed (native), installable`). This is an omission in the text formatter, not a code bug — the underlying data is correct — but there is drift between what the README implies is user-visible and what the CLI actually shows.

- **`uninstallCursorHooks` backup created even when file is absent:** `backupIfExists` at `hooks.ts:514` is a no-op when the file doesn't exist, so no spurious backup is written. However the subsequent `writeText` call still runs, creating the file (as covered in Finding 1). Once Finding 1's short-circuit is applied, both the backup and the write are skipped cleanly.

- **No test for `uninstallCursorHooks` on a missing `~/.cursor/hooks.json`:** Closing the test gap would directly catch Finding 1 and keep the ghost-file regression from re-appearing.

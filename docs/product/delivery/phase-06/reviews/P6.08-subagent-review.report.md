**F1 — `AttentionBubbleView.setHovered` does not reset `actionButton.alphaValue` when `isHidden = true`**

- File: `apps/menubar/Sources/AttentionBubblePanel.swift`, lines 267–275
- What is wrong: When `configure` is called with `review_ready` (or any default case), `actionButton.isHidden = true` is set. At line 246, `setHovered(false)` resets hover state. Alternatively, in `setHovered`, always set `actionButton.alphaValue = alpha` and let `isHidden` prevent taps, removing the `if !actionButton.isHidden` guard so the alpha is always kept consistent.

**Advisory Observations**

- **Doc-vs-code drift — dismiss does not return pet to `idle` pose**: The ticket Rationale states "Dismiss (`×`) clears `attention` from the bubble view and causes the pet to return to `idle` pose." The implementation's `dismissBubble()` (AttentionBubblePanel.swift:330–332) calls only `window?.orderOut(nil)`. No callback or notification causes `FloatingPetPanelController` to reset `ActivityState` to `.idle` or call `apply(state: .idle, ...)`. The pet's animation continues in whatever state `LivePollingDriver` last applied (`standby`, `errored`, etc.). Whether the spec clause "causes the pet to return to idle pose" was intentionally dropped during implementation or is still required is a product decision; this is documented here for the primary agent to resolve.

- **Unparseable `expiresAt` treated as not-expired (indefinite bubble)**: An `expiresAt` string that passes JSON decoding but is not a valid ISO 8601 date (e.g. `"never"`, `"TBD"`, a future schema change) causes `isExpired()` to return `false`, showing the bubble indefinitely. The P6.07 strategy chose this as the safe default (fail open → show), but in a production scenario a permanently visible bubble with no TTL decay is a user-facing annoyance. No action required given the spec permits it; flagged for awareness.

- **Dismiss does not reset `attentionActive`**: After the user dismisses the bubble via `×`, `attentionBubble` is hidden via `window?.orderOut(nil)`. But `attentionActive` in `FloatingPetPanelController` remains `true`. On the next `show(frame:)` call (e.g. the user hides then re-shows the floating pet), `repositionAndShowBubble()` will be called and the bubble will reappear without a new `applyAttention` call. This matches the spec ("session-local dismiss… if user relaunches, bubble may reappear"), but the same-session re-show behavior may surprise users who dismissed intentionally and then toggled the floating pet. The spec does not explicitly address intra-session re-show after dismiss.

- **`performAction` uses deprecated `NSRunningApplication.activate(options:)`**: On macOS 14+, `NSRunningApplication.activate(options:)` is deprecated in favor of `NSRunningApplication.activate()`. Silent failure on deprecation removal in a future OS; worth noting for a future maintenance pass.

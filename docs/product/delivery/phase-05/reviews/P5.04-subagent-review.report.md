**Actionable findings**

**Finding 1**
- **File:** `apps/menubar/Sources/PetStoreSeeder.swift`, lines 43–48
- **What is wrong:** When a source asset is absent from the bundle, the seed loop silently `continue`s with no log. On every subsequent app launch, `isCanonicalStoreComplete` returns `false` (store is permanently incomplete), triggering a no-op seed attempt that again silently skips missing assets. The result is a per-launch silent failure cycle that operators cannot detect or diagnose.
- **Clause:** Finding-discipline clause 3 (Spec-permits-real-bug). The spec states source-missing assets are "silently skipped" — that literal contract permits this undetectable repeated failure.
- **Fix recommendation:** Add an `NSLog` when a source asset is absent so the behavior is diagnosable: `guard fm.fileExists(atPath: src.path) else { NSLog("PetStoreSeeder: bundle asset '%@' missing — store will remain incomplete", asset); continue }`. This does not change the degraded behavior but makes it observable in Console.app.

**Finding 2**
- **File:** `apps/menubar/Sources/PetStoreSeeder.swift`, `seed(from:into:)` / `isCanonicalStoreComplete(at:)`
- **What is wrong:** `isCanonicalStoreComplete` checks only file presence. A `pet.json` that exists but is malformed (corrupted, truncated, or missing `spritesheetPath`) is reported as "complete," but `CodexPet()` will throw `petJsonMalformed` every launch. The seeder cannot overwrite the corrupted file (by invariant 1), leaving the app permanently on the pawprint icon with no recovery path and no guidance to the user.
- **Clause:** Finding-discipline clause 3 (Spec-permits-real-bug). Invariant 1 ("existing files are never overwritten") permits this unrecoverable state.
- **Fix recommendation:** The primary agent should decide between two options: (a) add a `pet.json` content-validity check inside `isCanonicalStoreComplete` (attempt decode; return `false` if malformed, allowing re-seed to skip it since the seeder only copies when the destination is absent — this still can't recover a corrupt existing file); or (b) document that a corrupted canonical store requires manual deletion of `~/.codogotchi/pets/maew/` to recover, and add an `NSLog` at the `petJsonMalformed` catch site in `MenubarApp` to name the offending file path. Option (b) is lower risk and consistent with the existing design.

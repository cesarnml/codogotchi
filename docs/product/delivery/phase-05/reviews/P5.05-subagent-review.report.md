**Invariant results**

**Invariant 1** — `[broken]` — A TOCTOU race exists between `FileManager.default.fileExists(atPath: url.path)` and `data.write(to: url, options: .atomic)`. `.atomic` uses `rename(2)` under the hood; if `config.json` is created (e.g. by a concurrently launched `codogotchi hooks install`) in the window after the existence check returns `false` but before the rename completes, the rename silently replaces it. The byte-content guarantee from Invariant 1 is not upheld in that race window.

**Invariant 2** — `[held]` — `AppStatePayload` is a private `Codable` struct with three optional fields. Swift's synthesized `Codable` ignores unknown JSON keys during decode, so pre-P5 files that omit the new keys decode cleanly with `nil`. Round-trip is tested explicitly in `testOnboardingAndHookActivityRoundTrip` and `testNewOptionalFieldsDefaultToNilWhenAbsent`. Both paths pass.

**Invariant 3** — `[held]` — `fetch()` guards on `exitCode == 0` first, then on `data(using: .utf8)` non-nil, then decodes via a `do/catch` that rethrows as `parseFailed`. Swift `Codable` requires all non-optional `Platform` fields to be present; partial JSON would throw and be caught. No default-initialized snapshot or partial result escapes.

**Surface results**

**S1 — ConfigBootstrap overwrite-guard** — `[probed]` — TOCTOU confirmed (see Finding 1). The symlink sub-case is safe: `fileExists(atPath:)` follows symlinks; if the target exists the check returns true and the function returns `.alreadyExists`. A dangling-symlink `config.json` (target absent) would pass the check and `.atomic` would create a regular file at the symlink path (replacing the symlink), not write through it — acceptable.

**S2 — Schema shape vs. TS CLI** — `[probed]` — `ConfigBootstrap` writes `{ profile_id, pet, features: { rpg_enabled } }`. The CLI's `hooks install` in `router.ts:413` errors only if `config.json` is _missing_; it does not validate schema shape. Shape matches the expected CLI contract. Clean.

**S3 — Read-modify-write race in `refreshHookStatusCache`** — `[probed]` — `refreshHookStatusCache` is called from `applicationDidFinishLaunching` on the main thread, and `HookStatusClient.fetch()` blocks the main thread via `process.waitUntilExit()`. NSRunLoop cannot deliver drag-generated frame-change events while the main thread is blocked. After fetch returns, the load→save sequence is synchronous on the main thread. No interleaving is possible at launch or wake time. Clean.

**S4 — `/usr/bin/env codogotchi` PATH resolution** — `[probed]` — If `codogotchi` is absent from the app-launch PATH, `env` returns exit code 127. `fetch()` throws `commandFailed(exitCode: 127, stderr: …)`, `refreshHookStatusCache` catches and logs, returns without touching cached state. Benign. Clean.

**Actionable findings**

1. **`ConfigBootstrap.swift:21–40` — Invariant 1 broken by TOCTOU race (Clause 1)**

   `fileExists(atPath: url.path)` returns `false` and then `data.write(to: url, options: .atomic)` atomically renames a temp file onto `url`. Between those two calls another process (e.g. the CLI's `hooks install`, a concurrent app launch, or a login-item race) can create `config.json`. The `rename(2)` call embedded in `.atomic` will silently replace it, overwriting a file the caller was told does not exist.

   **Shortest patch concept:** replace the existence-check + unconditional write with an exclusive-create flag so the write fails if the file appeared after the check:
   ```swift
   // Instead of write(to:options:.atomic):
   guard let fd = open(url.path, O_WRONLY | O_CREAT | O_EXCL, 0o644), fd >= 0 else {
       // errno == EEXIST → file was created in the race window → return .alreadyExists
       if errno == EEXIST { return .alreadyExists }
       throw Failure.writeFailed(underlying: POSIXError(POSIXErrorCode(rawValue: errno)!))
   }
   // write data to fd, close, done
   ```
   Alternatively: drop the pre-check, attempt the write with `O_EXCL`, and map `EEXIST` to `.alreadyExists`. This collapses the check-then-act into a single atomic syscall.

**Advisory Observations**

- **`isHooksNotActive` ignores `installable_in_phase`:** The predicate fires "active" on any platform with `installed && firingRecently`, including the three phase-deferred platforms (cursor, vscode, antigravity) that the CLI always sets to `installed: false` today. If a CLI bug or hand-edited snapshot sets one of those to active, the onboarding CTA would suppress itself for a non-real integration. A guard like `.filter { $0.installableInPhase }` before the `contains` call would make the predicate defensive against schema drift.

- **`lastEventAt` string propagation without ISO validation:** `refreshHookStatusCache` uses string `max()` to pick the most recent event timestamp. ISO 8601 UTC strings with uniform sub-second precision sort correctly lexicographically, but mixed-precision or non-UTC strings would produce a wrong winner. If a future CLI version changes the timestamp format, the stored `lastHookActivityAt` silently becomes a garbled ordering artifact rather than a hard error. A simple prefix-length guard or `ISO8601DateFormatter` parse before the `max()` would make the failure loud.

- **Phase 04 → Phase 05 downgrade drops new fields on re-save:** A developer switching back to a P4 build will silently lose `onboardingCompletedAt`, `lastHookActivityAt`, and `hooksStatus` from `app-state.json` on the first frame drag or visibility toggle. This is by design per the ticket Rationale but is not documented in the file format comment. A one-line comment on `APP_STATE_SCHEMA_VERSION` noting "P5.05 additive fields are lossy on P4 re-save" would help future readers avoid version-bump confusion.

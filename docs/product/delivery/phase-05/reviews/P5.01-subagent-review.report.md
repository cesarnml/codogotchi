**Actionable findings**

**1. `configList` mis-redacts Lite configs**

- **File:** `packages/cli/src/config-command.ts` (`configList`, ~257–266)
- **What's wrong:** For Lite configs, `config.github_token` and `config.wakatime_key` are `undefined`. The expression `undefined === null` is false, so both are set to `"<set>"`. Output invents credential keys that were never stored, contradicting the greenfield Lite shape and the Green note to fix redaction for omitted keys.
- **Clause:** Breaks invariant #1 (Lite shape fidelity) / correctness gap #2.
- **Fix:** Only redact keys that exist on the parsed config, e.g. guard with `'github_token' in config` / `'wakatime_key' in config`, or skip redaction entirely when `!config.features.rpg_enabled`.

**2. Invalid/legacy config throws unhandled `Error` through router**

- **Files:** `packages/cli/src/config.ts` (`readConfig`), `packages/cli/src/router.ts` (`sync`, `loot`, `vacation`, `config` branches)
- **What's wrong:** Schema validation throws a plain `Error`. Router catches only `ConfigCommandError`; `bin/codogotchi.ts` has no top-level handler. An operator with a pre-P5.09 config gets a stack trace instead of a clean stderr message + exit 2 — still "not implicitly RPG," but a rough failure mode on a path the ticket explicitly cares about.
- **Clause:** Correctness gap #2 / spec-permits-real-bug (rejection is correct; unhandled throw is unsafe UX).
- **Fix:** Throw `ConfigCommandError` from `readConfig` (or wrap `readConfig` in router with a catch that writes the message to stderr and returns exit 2).

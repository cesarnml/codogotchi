**Actionable findings**

**Finding 1 — Data-loss window in `PetImportHelper.importPet`**
File: `apps/menubar/Sources/PetImportHelper.swift:49–52`

The code:
```swift
if fileManager.fileExists(atPath: destination.path) {
    try fileManager.removeItem(at: destination)
}
try fileManager.copyItem(at: source, to: destination)
```
If `removeItem` succeeds and `copyItem` then fails (disk full, permission change mid-copy, signal), the canonical destination directory is permanently gone. The user's previously-imported pet is unrecoverable from within the app.

**Clause:** Spec-permits-real-bug — the ticket does not require atomic copy, but the behavior is a data-loss path under production conditions.

**Recommended fix:** Rename the existing destination to a `.bak` sibling before the copy, restore it on `copyItem` failure, and remove the backup on success:
```swift
let backup = canonicalPetsRoot.appendingPathComponent("\(id).bak", isDirectory: true)
if fileManager.fileExists(atPath: destination.path) {
    try fileManager.moveItem(at: destination, to: backup)
}
do {
    try fileManager.copyItem(at: source, to: destination)
    try? fileManager.removeItem(at: backup)
} catch {
    try? fileManager.moveItem(at: backup, to: destination)
    throw error
}
```

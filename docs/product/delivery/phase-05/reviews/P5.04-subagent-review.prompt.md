### Attack surfaces to probe

1. **`PetStoreSeeder.seed` — missing-source-file silent skip**: when a required asset is absent from the bundle source directory, the seed silently continues. Does this mean `isCanonicalStoreComplete` could return `false` after a partial seed, causing repeated seed attempts on every launch? Is there a log or way for operators to detect a partial bundle?

2. **`CodogotchiPet.init` — `CodogotchiManifest` JSON decoding**: `CodogotchiManifest` no longer declares `spritesheetPath`. If an existing `pet.json` on disk has `"spritesheetPath"` as a top-level key, does the decoder fail or silently ignore the unknown field? Verify the `convertFromSnakeCase` strategy handles unknown keys gracefully.

3. **`CodexPet.defaultPetDirectoryPath` + `CodogotchiPet.defaultPetDirectoryPath` — CODOGOTCHI_HOME race**: both methods call `getenv("CODOGOTCHI_HOME")` at call time (not cached). The `PetConfig.resolvedPetName()` call inside also reads `CODOGOTCHI_HOME` for the config path. If the env var is set mid-session (e.g. in tests), do the two reads agree? Is there any TOCTOU concern between the outer path build and the inner `resolvedPetName()` call?

4. **`MenubarApp.bundledMaewDirectory` — bundle absent in test/partial-build context**: the helper returns `nil` when `Bundle.main.resourceURL` is nil or the `maew` subdirectory is absent. Does `MenubarApp.applicationDidFinishLaunching` degrade cleanly when `bundledMaewDirectory()` returns `nil`? Confirm no seed path is skipped but app still launches.

5. **`Fixtures/maew/pet.json` — `spritesheetPath: "spritesheet.webp"` change breaks `CodogotchiPet` fixture test**: `testLoaderSucceedsFromFixtureDirectory` in `CodogotchiPetTests` loads from `Fixtures/maew/`. `CodogotchiPet` now ignores `pet.json.spritesheetPath` and hardcodes `"codogotchi-spritesheet.webp"` — verify this test still passes and the fixture still has `codogotchi-spritesheet.webp` present.

6. **`PetStoreSeeder.requiredAssets` — canonical list vs. runtime assumptions**: `isCanonicalStoreComplete` checks only the three required filenames. `CodexPet.init` reads `pet.json.spritesheetPath` to locate the Codex sheet — if `pet.json` in the store is missing `spritesheetPath`, `CodexPet` would throw `petJsonMalformed`. Is `requiredAssets` checking file presence sufficient, or does it need to validate `pet.json` content?

**Actionable findings**

**Finding 1 — Unparseable `expires_at` silently activates gate indefinitely**

`GateJsonReader.swift:22` — `isExpired` returns `false` when `expiresAt` fails both ISO 8601 parse passes. If gate.json is written with a corrupt or non-ISO `expires_at` value (e.g., a Unix timestamp integer accidentally stringified as `"1748476800"` or a localized date string), `isExpired` returns `false`, condition B passes, and the gate may activate and stay active permanently until the file is removed. The reader does not reject records with unparseable `expires_at`; it successfully decodes them. The resolver then treats them as unexpired.

**Severity:** Medium — requires a malformed write from the orchestrator, but the failure mode is invisible (no log, no nil, gate just never expires).

**Suggested fix:** In `resolveActivityState`, treat an unparseable `expiresAt` as expired by changing `isExpired` return-on-fallthrough from `false` to `true`. Alternatively, add a guard in `GateJsonReader.read` that validates `expiresAt` is parseable before returning a snapshot.

---

**Finding 2 — Reader tests do not catch a regressed `GateJsonReader.read` returning valid snapshots for partial-field inputs**

`GateJsonReaderTests.swift:49` — `testGateJsonMissingGateFieldReturnsNil` tests one missing-field case (`gate` absent). There is no test for `expires_at` absent or `since` absent. If a future refactor accidentally made `expires_at` optional in the guard chain, no test would fail. The coverage is incomplete for the "all three fields required" invariant.

**Severity:** Low — guard is currently correct, this is a test-gap, not a runtime bug.

**Advisory Observations**

- **One-tick gate/state skew is real but accepted.** `state.json` is read first in `runTick()`, then `gate.json` is read in `decide()`. On a fast-writing orchestrator, these two reads could see different epochs. A single-tick visual glitch (gate activates one tick early, or hook state appears one tick after gate file is written) is the worst case. The design explicitly accepts this in favor of simplicity; no fix needed, but worth calling out for future debugging if users report one-frame flickers on gate transitions.

- **`testUnexpiredGateWithArtlessStateRendersHookState` tests `advance` by name in a comment, but `ActivityState.advance` must exist as an enum case for the test to compile.** If `.advance` is ever removed from `ActivityState`, the test will fail to compile rather than fail to run — good signal. Noted only because the comment says "advance is in ActivityState but not in CodogotchiPet.rowMap" and that invariant is worth keeping visible.

- **`resolveActivityState` is a free function, not a method.** It has no natural home — it lives in `GateJsonReader.swift` despite depending on `CodogotchiPet.rowMap`. This is a coupling note for Phase 17 when `.advance` gains a row: the rowMap update, the test update, and this function are all in different files. Not a bug, but a future-confusion vector.

**Advisory Observations**

- **Stop event preserves readRun across the standby boundary.** At `hook-binary.ts:195`, the Stop/standby branch returns `readRun: prior.readRun`. This means a sequence of Read×2 → Stop → Read×1 produces cramming (prior.readRun=2, nextRun=3 ≥ 3). No test covers this scenario. The invariant only mandates reset on write tools, so this is technically compliant, but the behavior could surprise: the gotchi enters cramming state immediately after a standby event if the session resumes with a single Read. If the intent is that Stop acts as a streak break, a `readRun: 0` return on the standby branch would need a spec change and a new test.

- **Read-only sed not tested.** The `sed -i` test (line 800) documents the rationale as "write command," which is accurate. A read-only `sed 's/foo/bar/'` (no `-i`) also falls to implementing because `sed` is absent from `THINKING_BASH_PREFIXES` entirely. There is no test for the no-`-i` form. This is not a bug — the behavior is correct per spec — but the test gap leaves future maintainers with only the "write command" comment as guidance, which could invite adding `sed` back to the thinking list as a "read-only optimization" regression.

### Ticket scope

**Outcome:**
- A `PetAssetResolver` resolves a `petId` to `(CodexPet, CodogotchiPet?)`, loading assets from `~/.codogotchi/pets/<petId>/` (and the bundled Maew path for `maew`).
- Results are cached by `petId`: resolving the same id twice loads the spritesheet once; two origins assigned the same pet share one loaded `CodexPet`.
- A load failure for a non-Maew pet (missing/corrupt sheet) falls back to the Maew assets rather than throwing, so a window always has something to render.
- `evict(petId:)` (or `evictAll()`) drops cached entries so a reassignment re-resolves fresh assets.

**Rationale notes:**
- Cache is a plain `Dictionary` — not thread-safe; MenubarApp calls pet loading on the main actor only.
- Injectable loader closures for tests; real defaults delegate to `CodexPet(petDirectory:)` / `CodogotchiPet(petDirectory:)`.
- `resolveMaewFallback()` checks the cache first before loading.
- Fallback for non-maew load failure is logged via `NSLog`.
- Throws only when the maew fallback itself cannot be loaded.

### Invariants to hold

1. `resolve(petId:)` must return the same `CodexPet` instance on a second call for the same `petId` (cache-key is `petId`, not directory path or origin).
2. `resolve(petId:)` must never throw to the caller when the petId is not `DEFAULT_PET_NAME` ("maew") — a load failure for any non-maew pet must silently fall back to the bundled maew assets.
3. After `evict(petId:)` or `evictAll()`, the next `resolve(petId:)` must reload from disk (loader closure invoked again) rather than returning a stale cache entry.

### Attack surfaces to probe

1. `resolve(petId:)` — cache identity: the cache key is the string `petId`. If a caller passes `"maew"` vs the constant `DEFAULT_PET_NAME`, they must be equal. Probe whether `DEFAULT_PET_NAME` being a module-level `let` (not a type member) is consistent across the resolver and test usage.

2. `resolve(petId:)` fallback path for maew itself — the guard `guard petId != DEFAULT_PET_NAME else { throw error }` is inside the `catch` block. Probe whether this allows the maew case to re-throw through the `do/catch` when `codexLoader(maewFallbackURL)` fails, and whether `resolveMaewFallback()` is called instead of rethrowing in that case.

3. `resolveMaewFallback()` — double-fallback caching: when a non-maew pet fails and triggers fallback, `resolveMaewFallback()` caches the result under `DEFAULT_PET_NAME`. Probe whether a second non-maew failure for a different `petId` returns the already-cached maew entry (correct), and whether the failing petId is ever incorrectly cached under the failing petId's key.

4. `petsBaseURL(petId:)` — path injection: `petId` is appended directly to the pets base URL with `appendingPathComponent`. Probe whether a petId containing path traversal characters (`../`, absolute path `/`, or URL-encoded separators) could escape the pets directory boundary.

5. `defaultMaewFallbackURL()` — bundle availability: `Bundle.main.resourceURL` returns nil in command-line tool contexts and potentially in tests. The production test host app should have the bundle, but verify that the injected `maewFallbackURL` parameter prevents tests from ever calling `defaultMaewFallbackURL()`.

### Diff context

The diff introduces a single new Swift file `PetAssetResolver.swift` with these key behaviors:

1. `resolve(petId:)` dispatches to `maewFallbackURL` when `petId == DEFAULT_PET_NAME`, otherwise builds `petsBaseURL(petId:)`. It calls `codexLoader(dirURL)` (throws on failure) and `try? codogotchiLoader(dirURL)` (soft-degrades). On success, both are cached under `petId` and returned.

2. On `codexLoader` failure, the `catch` block checks `petId != DEFAULT_PET_NAME` — if petId IS maew, it rethrows. Otherwise it logs and calls `resolveMaewFallback()`.

3. `resolveMaewFallback()` checks `cache[DEFAULT_PET_NAME]` first, then calls `codexLoader(maewFallbackURL)` and `try? codogotchiLoader(maewFallbackURL)`, caches under `DEFAULT_PET_NAME`, and returns.

4. `evict(petId:)` calls `cache.removeValue(forKey: petId)`. `evictAll()` calls `cache.removeAll()`.

5. `petsBaseURL(petId:)` reads `CODOGOTCHI_HOME` env var or uses `~/.codogotchi/` as base, then appends `pets/<petId>`.

6. `defaultMaewFallbackURL()` uses `Bundle.main.resourceURL?.appendingPathComponent("maew")` with a fallback to `~/.codogotchi/pets/maew`.

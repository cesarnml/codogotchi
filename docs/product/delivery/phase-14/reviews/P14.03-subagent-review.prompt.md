### Ticket scope

**P14.03 Swift: AssignmentsJsonReader + writer + migration seed**

Outcome:
- `AssignmentsJsonReader.read(at:)` reads `~/.codogotchi/assignments.json` and returns an `AssignmentsSnapshot` with safe defaults (`default = "maew"`, no platform overrides) on any IO/decode failure.
- `AssignmentsSnapshot.resolve(origin:)` returns the override petId for an origin, or the `default` petId when the origin has no override. `combined` always resolves to `default`.
- `AssignmentsJsonWriter.write(badge:petId:to:)` persists a single badge assignment through `ConfigFileWriter.merge`, enforcing that each badge key holds exactly one petId.
- `AssignmentsMigration.seedIfAbsent(assignmentsURL:configURL:)` is a one-time idempotent seed: if `assignments.json` is absent, raw-reads `config.json`'s `pet` key via `JSONSerialization` (schema-independent, fallback `DEFAULT_PET_NAME`), and writes a minimal `assignments.json` with `default` set to that pet. Re-running when `assignments.json` exists is a no-op.
- `applyBadgeAssignment(badge:petId:in:)` is a pure free function for in-memory badge-assignment updates shared with P14.07.

Rationale (key trade-offs):
- `keyDecodingStrategy = .convertFromSnakeCase` was intentionally NOT used because it conflicts with explicit `CodingKeys` — the decoder converts JSON snake_case keys before matching them against `CodingKey.stringValue`, causing explicit snake_case raw values to fail to match.
- `AssignmentsPayload` uses explicit `CodingKeys` to handle the `"default"` JSON key (a Swift reserved word) without backtick property names in the struct.
- `ASSIGNMENT_BADGE_KEYS` constant exported for callers; P14.07's ViewModel validates badge keys in the UI layer.
- Migration failures are silently swallowed (`try?`) so a migration hiccup never crashes the pool.

## Intended Outcome

P14.06 adds a Swift menubar `minimalist` platform window mode:

- `CustomizationJsonReader.PlatformMode` accepts `"minimalist"` while preserving schema version 1 and unknown-mode fallback to `.own`.
- `FloatingPetWindowPool` routes origins configured as `.minimalist` to a minimalist window factory keyed per origin, not to combined mode and not to the normal pet window factory.
- Minimalist windows conform to `FloatingPetWindowControlling`, preserve the pool's existing lifecycle semantics, and participate in spawn, idle-dismiss TTL, hide/show, hidden-state, last-active, and frame persistence.
- Minimalist windows render a compact badge strip with platform, animation, attention, and latest-prompt summary text. They must not render a pet sprite or RPG HUD.
- `PromptAttentionReader` reads `~/.codogotchi/prompt-attention.json`, looks under `by_session`, filters session keys by `<origin>:` prefix, selects the newest parseable `updated_at`, and returns that entry's summary. Missing, malformed, foreign-origin, or unparseable input should degrade to an empty summary.

## Core Invariants To Attack

1. For any origin whose effective `PlatformMode` is `.minimalist`, `FloatingPetWindowPool.update(snapshot:)` must create and update exactly one origin-keyed minimalist controller via `minimalistWindowFactory`, not the normal pet `windowFactory`, while preserving existing TTL, hidden-state, hide/show, frame-save, and last-active behavior.
2. `MinimalistWindowController.applyRPGState` must be a no-op, and the minimalist path must not instantiate `FloatingPetScene`, `FloatingPetPanelController`, RPG HUD controls, pet sprite chrome, or separate badge popover windows.
3. `PromptAttentionReader.latestSummary(origin:at:)` must isolate by `<origin>:` prefix, select only the newest parseable matching entry, and return empty for absent, malformed, stale, foreign-origin, or unparseable data without cross-platform leakage.
4. The customization schema remains backward compatible: schema version unchanged, `"minimalist"` maps to `.minimalist`, and unknown mode strings still degrade to `.own`.

## Attack Surfaces

- Pool routing: `.minimalist` should behave like an own-origin mode for keys and TTL, not like `.combined` or `.off`. Check `windowKey(for:)`, `lastSeenForWindow`, `activeWindows`, hidden origins, and dismissal cleanup.
- Factory fallback: `minimalistWindowFactory` is optional in tests. Verify missing factory behavior cannot silently ship a sprite/HUD pet window for production minimalist mode, and that `MenubarApp` actually supplies the minimalist factory.
- Visibility and persistence: `MinimalistWindowController` should save frames through `FloatingFramePolicy`, call `onVisibilityChanged`, respect hidden state, and not respawn a manually hidden origin until the pool logic allows it.
- Prompt reader boundary: probe missing file, malformed JSON, missing `by_session`, foreign origins, empty summaries, unparseable dates, and equal or out-of-order timestamps. Make sure `codex:` cannot read `cursor:` summaries and prefix matching cannot accidentally match a wider origin.
- No-HUD contract: inspect whether any code path creates `FloatingPetPanelController`, `FloatingPetScene`, `AttentionBubblePanel`, or RPG HUD surfaces for minimalist windows. The ticket asks for badge/attention composition; the implementation uses a new compact strip view, so decide whether this is an acceptable implementation detail or a product/spec drift.
- Settings integration: the picker should expose Minimalist without breaking save/load, defaulting, star-default selection, or unknown-mode fallback.
- Existing workflows: `reloadActivePet`, `showHUDDemo`, debug tools, active-window iteration, and platform default behavior should not regress when a minimalist origin is present.

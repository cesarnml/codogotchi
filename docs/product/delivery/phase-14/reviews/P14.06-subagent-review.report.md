**Findings**

1. **Unparseable prompt timestamps can still surface a summary. Actionable for P14.06.**  
   [CodogotchiFolders.swift](/Users/cesar/code/codogotchi_p14_06/apps/menubar/Sources/CodogotchiFolders.swift:75) filters by origin and non-empty summary, then ranks with `parseDate(...) ?? .distantPast`. If the only matching `codex:` entry has `"updated_at": "bad"` and a summary, `latestSummary` returns that summary instead of empty. The ticket says select the newest **parseable** entry and degrade unparseable input to empty. Add a test for “matching origin, non-empty summary, unparseable date only” and filter out nil dates before `max`.

2. **`.minimalist` can silently fall back to the normal pet/HUD window factory. Actionable for P14.06.**  
   [FloatingPetWindowPool.swift](/Users/cesar/code/codogotchi_p14_06/apps/menubar/Sources/FloatingPetWindowPool.swift:179) uses `minimalistWindowFactory?(origin) ?? windowFactory(origin, petId)`. That violates the core invariant that minimalist mode must route to the minimalist factory and never instantiate sprite/HUD pet chrome. Production does wire the factory in [MenubarApp.swift](/Users/cesar/code/codogotchi_p14_06/apps/menubar/Sources/MenubarApp.swift:251), but the pool contract itself is fail-open. Prefer making the factory non-optional or failing closed/preconditioning when a `.minimalist` origin is encountered without one.

3. **Minimalist windows do not preserve the normal frame-change persistence path. Actionable unless intentionally deferred.**  
   Normal pet windows wire committed frame changes through `setFrameChangeHandler` into persistence at [FloatingPetController.swift](/Users/cesar/code/codogotchi_p14_06/apps/menubar/Sources/FloatingPetController.swift:78) and [FloatingPetPanel.swift](/Users/cesar/code/codogotchi_p14_06/apps/menubar/Sources/FloatingPetPanel.swift:702). The minimalist protocol has only show/hide/apply methods at [FloatingPetController.swift](/Users/cesar/code/codogotchi_p14_06/apps/menubar/Sources/FloatingPetController.swift:207), and `MinimalistPanelController` creates a borderless panel without an equivalent drag/frame-change persistence hook at [FloatingPetPanel.swift](/Users/cesar/code/codogotchi_p14_06/apps/menubar/Sources/FloatingPetPanel.swift:60). This misses the ticket’s “frame persistence” parity unless minimalist strips are intentionally fixed-position for this phase.

**Checked**

Schema compatibility looks fine: `.minimalist` is a raw-value enum case, unknown modes still degrade to `.own`, and config writes still seed/preserve schema version 1. The no-HUD implementation is structurally separate from `FloatingPetPanelController` in the production factory path, but finding #2 weakens that guarantee at the pool boundary.

### Ticket scope

**Outcome:**
- The `FloatingPetWindowPool` window factory resolves each origin's pet via `AssignmentsJsonReader.resolve(origin:)` + `PetAssetResolver` instead of a single captured global pet — two own-mode origins with different assignments render different pets.
- The combined-mode window renders the **Default** pet (`resolve` for `combined` → `default`).

- The combined window renders a persistent ⭐ **Default** platform badge while idle (the window badge renderer gains a `.default` star case), resolving the prior asymmetry where own-mode windows badge always but the combined window only badged when active.

- `reloadActivePet` calls `evictAll()` for simplicity; per-badge eviction is a micro-optimisation deferred to P14.07/08.
- `replacePets` broadcast removed from pool; old test renamed/updated to use new per-origin API.

### Attack surfaces to probe

1. **`FloatingPetWindowPool.update` — petId flow on re-spawn vs. first-spawn**: The `petId` is resolved at spawn time (`windows[origin] == nil`). If an origin's assignment changes between ticks, a window that already exists will NOT receive the new petId until it is evicted and respawned. Probe whether the ticket's stated contract (reassignment → respawn via `replacePet`, not via evict-and-spawn) is consistently enforced, or whether a lingering existing window silently shows the wrong pet.

2. **`MenubarApp.reloadActivePet` — `petAssetResolver` optional chaining**: `petAssetResolver` is stored as `var petAssetResolver: PetAssetResolver?`. In `reloadActivePet`, the call is `try? self.petAssetResolver?.resolve(petId: petId)`. If `petAssetResolver` is nil (e.g. `CodexPet()` threw during launch so the pool was never created), the entire for-loop silently no-ops and windows are never updated. Probe whether this nil case is reachable and harmful.

3. **`PlatformAttribution.init?(origin:)` + combined badge application in pool Step 8**: The pool calls `windows["combined"]?.applyPlatform(origin: "combined")` only when `winner.activityState == .idle`. The `FloatingPetController.applyPlatform` implementation must handle `origin: "combined"` by resolving `PlatformAttribution(origin: "combined") == .default`. Probe whether the `.default` case actually reaches the badge-rendering path, or whether a switch/guard somewhere silently drops the new case.

4. **`AssignmentsMigration.seedIfAbsent` config URL construction in `MenubarApp`**: The seed call constructs `configURL` via `URL(fileURLWithPath: config.pollingTarget.path).deletingLastPathComponent().appendingPathComponent("config.json")`. `pollingTarget.path` is a `state.d/` or similar polling directory — not a file. Probe whether `deletingLastPathComponent()` of a directory URL actually yields the parent `~/.codogotchi/`, or whether it produces an unexpected path (e.g., if `pollingTarget.path` already ends with `/`, it strips nothing and the result is `state.d/config.json`).

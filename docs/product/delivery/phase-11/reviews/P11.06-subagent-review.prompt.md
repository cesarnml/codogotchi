### Ticket scope

**P11.06 Marketplace SPA — shell, gallery grid, pet detail + install card**

A single static Astro route hosts a React SPA island wired to the Convex client, with client-side routing for the gallery list, pet detail, and (placeholder for) upload — no SSR adapter; static hosting preserved.

- Gallery grid: cards rendering the static idle-frame thumbnail, displayName, by <username>, tier badges (Codex / Lite-Basic / Lite-Enhanced / SoA present), and download count; with search and Newest sort and pagination, fed by `listPetsForGallery` (new query added to convex/pets.ts).
- Pet detail: install card with the three install paths — `npx codogotchi add <id>`, the curl one-liner, and the direct `.zip` download — plus a per-tier readout (which tiers + sizes) and client-side sprite animation that cycles the 8 atlas frames of the downloaded sheet.
- `web/src/pages/pets.astro` redirects to `/gallery`; a footer disclaimer is present.

**Rationale:** Hash-based routing (`/gallery#<petId>`) avoids hosting-level SPA rewrite rules. Vite `~convex` alias resolves the generated Convex API types from outside the web package. `listPetsForGallery` resolves thumbnail storage URLs server-side to avoid N+1 round-trips. `client:only="react"` ensures Convex WebSocket setup never runs during SSG.

### Invariants to hold

1. The install strings rendered on the detail page must use the Convex HTTP endpoint URL (`.convex.site`) for the curl and zip download paths — not the Convex WebSocket/query URL (`.convex.cloud`) — because the download action is an HTTP action (P11.04), not a query.

### Attack surfaces to probe

1. `buildInstallStrings` in `installStrings.ts` — URL domain correctness: the download URL must use `apiBase` (`.convex.site`) but `apiBase` is passed in from `GalleryApp.API_BASE` — verify the constant is `.convex.site`, not `.convex.cloud`.
2. `listPetsForGallery` listed gate in `convex/pets.ts` — does `q.eq("listed", true)` carry through in the new query, or was it accidentally omitted when the query was refactored from `listPets`?
3. `PetDetail.tsx` ZIP object URL lifecycle — the useEffect cleanup revokes the object URL via `URL.revokeObjectURL`, but if `cancelled = true` the URL is revoked in the fetch callback; if the component is unmounted while the fetch is in-flight, the already-revoked objectUrlRef could be dereferenced in the cleanup.
4. `GalleryApp.tsx` module-scope `new ConvexReactClient(CONVEX_URL)` — does this execute during Astro's SSG pass even with `client:only="react"`? If so, it could fail or log errors in Node.js context at build time.
5. `getPet.downloadUrl` vs `buildInstallStrings` URL consistency — `getPet` returns `downloadUrl: /pets/${pet.petId}/download` (relative path), while `buildInstallStrings` constructs `${apiBase}/pets/${petId}/download` (absolute). The PetDetail component uses `buildInstallStrings`, not `pet.downloadUrl` — are both forms served by the same HTTP action endpoint from P11.04?
6. `pets.astro` redirect — the `return Astro.redirect("/gallery", 301)` syntax is correct for Astro, but the redirect target `/gallery` must exist as a static route in the build; verify the build output includes `/gallery/index.html`.

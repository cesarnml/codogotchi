**Actionable findings**
1. [convex/auth.ts](/Users/cesar/code/codogotchi_p11_07/convex/auth.ts:23) — New-user signup inserts usernames without authoritative server-side validation. `profile()` only calls `normalizeUsername`, and `createOrUpdateUser()` inserts `base`/`username` directly, so a direct auth request can create usernames with spaces or punctuation, overlength handles, or provider-derived values that `users.setUsername` would reject. This breaks Invariant 2 and finding-discipline clause 1. Fix: run `validateUsername` on every password-provided or synthesized username before querying/inserting, normalize before `by_username` lookup, and bound suffix generation so `_1`, `_2`, etc. cannot exceed `USERNAME_MAX`.

2. [convex/actions/uploadPet.ts](/Users/cesar/code/codogotchi_p11_07/convex/actions/uploadPet.ts:21) — Upload rejection paths leak staged storage blobs. Because the client uploads the raw zip and optional thumbnail before invoking the action, any early throw at lines 27-60 leaves the raw zip orphaned, and the invalid-package path at lines 64-70 leaves the staged thumbnail orphaned. This is a demonstrable correctness gap and also fits finding-discipline clause 3: the ticket spec permits “validator rejections are surfaced,” but the current implementation makes common rejected uploads accumulate unreachable storage. Fix: track staged `rawZipStorageId` and `thumbnailStorageId` and delete them in a top-level `catch`/`finally` on every failing path, keeping the existing canonical-zip cleanup for post-repack failures.

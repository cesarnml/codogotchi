### Invariants to hold

### Attack surfaces to probe

1. **`createOrUpdateUser` uniqueness loop in `auth.ts`** — the `while(true)` loop finds the first free username suffix. Does the loop terminate correctly if ALL suffixes up to N are taken? Is `attempt` initialized before the loop body where it increments? Could a race window between the `.unique()` check and the `db.insert` allow duplicate usernames in an adversarial concurrent scenario (two simultaneous sign-ups with the same base name)?

2. **`createUser` in `users.ts` — uniqueness check vs. `db.insert` ordering** — the uniqueness check reads then writes. In Convex, mutations are serialized so races between two `createUser` calls are impossible. Confirm this is actually safe: does the serialization guarantee hold even through the `@convex-dev/auth` callback path, or could the auth library invoke the callback from an action context where serialization is not guaranteed?

3. **`listPets` index usage** — `by_listed_createdAt` is a compound index `["listed", "createdAt"]`. Does `.withIndex("by_listed_createdAt", q => q.eq("listed", true)).order("desc")` correctly read the index in descending `createdAt` order for the `listed=true` partition? Could `.order("desc")` apply to the wrong field, returning results in an unexpected order?

4. **`migrateDropLegacyUsers` safety threshold** — the migration throws if `authUsers.length > 1`. On a fresh deployment, the auth-managed `users` table starts empty (length=0). On first run after a real user signs up, length=1 is allowed. The invariant is that the migration was designed to run BEFORE any real users sign up. What happens if an operator runs the migration after real users have signed up (e.g., length=5)? The throw is correct but the error message says "at migration time" — does the message give the operator enough to understand the resolution path?

5. **`schema.ts` — `...authTables` spread followed by `users: defineTable(...)` override** — the spread includes `authTables.users` (with `email` and `phone` indexes). The subsequent `users: defineTable(...)` definition in the same object literal replaces the spread entry. Confirm this override is the documented extension pattern and that the `email` + `phone` indexes from authTables are preserved in the override definition (they must be or auth flows break).

6. **`Password` provider `profile()` cast safety** — `params.email as string` is cast without a null check. If a user signs up via Password without an email (e.g., phone-only), `(params.email as string).split("@")[0]` would throw a runtime error. Does the Password provider guarantee `email` is present, or is this a silent failure path?

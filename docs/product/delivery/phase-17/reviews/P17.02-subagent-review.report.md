**Actionable findings**

- `apps/menubar/Sources/Windows/FloatingPetPromptDismissal.swift:80` — `uninstall()` begins with `guard let owner else { return }`. Both presenting views call it from their `deinit`, but Swift zeroes weak references before the owner’s deinitializer runs, so `self.owner` is nil and teardown returns without removing the notification observer or three AppKit event monitors. The dismissal object then deallocates, leaving globally registered monitor closures that weakly reference a dead object; repeated view destruction accumulates inert monitor registrations for the app’s lifetime. This is a demonstrated correctness gap under finding-discipline clause 2. Fix by making coordinator cleanup conditional on a live owner while always removing monitor tokens and clearing fields; also add `deinit { uninstall() }` to `FloatingPetPromptDismissal` as defensive ownership-local cleanup.

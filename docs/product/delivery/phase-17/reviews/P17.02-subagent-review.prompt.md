### Diff context

Two new files: `FloatingPetPromptBuilder.swift` defines `FloatingPetPromptCapabilities` (named
capability fields), `FloatingPetPromptHandlers` (one closure per possible item), and
`FloatingPetPromptBuilder.items(capabilities:handlers:) -> [FloatingPetPromptItem]`, a pure function
appending items conditionally in a fixed order (force-idle → rename → sync-label+prune →
mode-switch → panel-size → hide-all-others → hide-this). `FloatingPetPromptDismissal.swift` defines a
class with `install(owner:panel:dismiss:)` (registers with `FloatingPetPromptCoordinator.shared`, then
installs one `didResignActiveNotification` observer, one global mouse monitor, one local mouse monitor
gated on `event.window !== panel`, one global keyboard monitor) and `uninstall()` (tears all of that
down and calls `FloatingPetPromptCoordinator.shared.didDismiss(owner:)`).

`FloatingPetInteractionView.presentHidePrompt` and `MinimalistBadgeView.presentHidePrompt` were rewritten
to build a `FloatingPetPromptCapabilities` value from their existing per-shape state, wrap each real
handler in a `{ self?.dismissHidePrompt(); self?.<realHandler>?() }` closure inside
`FloatingPetPromptHandlers`, call `FloatingPetPromptBuilder.items(...)`, then call
`promptDismissal.install(owner: self, panel: panel) { self?.dismissHidePrompt() }` instead of the old
per-view `installHidePromptDismissObservers()`. `MinimalistBadgeView.presentPanelSizePill` was similarly
rewritten to use a second `FloatingPetPromptDismissal` instance (`sizePillDismissal`). All four old
per-view `install*DismissObservers`/`remove*DismissObservers` methods and their monitor/observer-array
properties were deleted; `dismissHidePrompt`/`dismissSizePill` now just call `.uninstall()`.

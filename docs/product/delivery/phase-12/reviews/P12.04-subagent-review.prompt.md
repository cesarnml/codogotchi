### Ticket scope

**Outcome:**
- The `POST /sync` handler in `convex/http.ts` requires a shared-secret header (`x-codogotchi-sync-secret`) and rejects with 401 any request lacking or mismatching it, checked against the `SYNC_SHARED_SECRET` Convex environment variable.
- When the env var is **unset**, the handler is dev-permissive (allows through) — not fail-closed. This is an explicit design choice documented in Rationale so local development is not silently broken.
- The CLI (`packages/cli/src/sync.ts`) reads the secret from `SyncDeps.syncSecret` and sends it as `x-codogotchi-sync-secret` on its `/sync` POST. `SyncDeps.syncSecret` is populated from `process.env.CODOGOTCHI_SYNC_SECRET` in `router.ts`.
- A valid-secret request still succeeds end-to-end (payload validation + `syncProfile` mutation unchanged).
- Scope note: This is shared-secret only. It does NOT stop an enrolled user from POSTing another user's `profile_id` — that is identity-grade auth, deferred to the leaderboard phase.

**Rationale notes:**
- Dev-permissive when `SYNC_SHARED_SECRET` is unset: existing production deployments without the env var are unaffected until the operator explicitly sets it.
- `CODOGOTCHI_SYNC_SECRET` is env-var-only on the CLI side — not stored in `~/.codogotchi/config.json`.
- Production sync posture confirmed: handler is safe to ship because the dev-permissive posture preserves backward compatibility for any live syncing buddies.

### Attack surfaces to probe

1. **`convex/http.ts` guard — empty-string env var:** If `SYNC_SHARED_SECRET` is set to `""` (empty string), the handler's `if (requiredSecret)` branch is falsy and the guard is skipped. Is this the intended behavior (treat empty = unset = dev-permissive), and is it consistent with the documented Rationale?

2. **`convex/http.ts` guard — header value coercion:** `request.headers.get("x-codogotchi-sync-secret") ?? ""` falls back to `""` when the header is absent. This means "absent header" and "header set to empty string" both produce `""` and are treated identically. If `SYNC_SHARED_SECRET` were `""`, the comparison `"" !== ""` is false, so it would pass — but the `if (requiredSecret)` guard already skips the check. Probe: is there any path where an empty header value could bypass a non-empty required secret?

3. **`packages/cli/src/sync.ts` — header when `syncSecret` is empty string:** `if (deps.syncSecret)` is falsy for `""`. So passing `syncSecret: ""` omits the header. Probe: does `router.ts` ever pass `""` (e.g. `process.env.CODOGOTCHI_SYNC_SECRET` resolving to `""`)? If so, the CLI omits the header while the server may or may not enforce.

4. **`router.ts` env var read:** `process.env.CODOGOTCHI_SYNC_SECRET` is undefined when unset — this is correctly passed as `syncSecret: undefined` which triggers the `if (deps.syncSecret)` falsy branch and omits the header. Probe: does `process.env.CODOGOTCHI_SYNC_SECRET` ever coerce to `""` in Bun's env handling? If so, the header is omitted for `""` — cross-check with the server behavior.

5. **`convex/http.ts` — 401 vs 403 status code:** The ticket says "rejects with 401/403". The implementation returns 401. Verify this is consistent and intended (401 = missing credentials, 403 = credentials present but unauthorized). A wrong secret could arguably be 403.

6. **Test isolation — `process.env` mutation:** `beforeEach`/`afterEach` in `http.test.ts` mutate `process.env.SYNC_SHARED_SECRET`. The existing `"POST /sync"` describe block (no env var set) runs in the same process. Verify that test ordering cannot cause the env var to leak between describe blocks if a test throws before `afterEach`.

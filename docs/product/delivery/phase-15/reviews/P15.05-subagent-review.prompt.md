### Ticket scope

P15.05 PlatformSessionBadge + in-memory free-list numbering (Codogotchi menubar app, pure AppKit — no SwiftUI).

Outcome (from the ticket doc):
- A per-platform free-list numbering allocator assigns each active session the lowest free
  number, starting at 1. A number returned by a vacated slot (pruned / aged / de-rendered-and-gone)
  re-enters the pool; the next new session takes the lowest free number. Under an Unlimited cap
  numbering stays purely monotonic (no bounded pool to reuse within). Numbers are never
  reassigned away from a live session.
- The allocator is in-memory, rebuilt at launch from the sessions observed on the first ticks;
  it holds no persisted state.
- A new `PlatformSessionBadge` view renders the session's label (default "Session N") horizontally
  centered beneath `PlatformChip` + `AnimationBadge` on both Own panels and Minimalist strips.
- In Minimalist mode the `AttentionBubble` anchor shifts down to make room for the badge; the badge
  respects the existing `minimalistBadgeScale`.
- Session numbering and the badge apply ONLY to session-keyed windows (`origin:session_id` render
  keys). Plain-origin windows (session-pets off) and the "combined" window must never show a
  session badge or consume a number.

Rationale notes (already recorded in the ticket doc, for cross-reference): the allocator is a
plain non-`@MainActor` type; Unlimited-ness is tracked as allocator-internal per-origin state via
`setUnlimited(_:origin:)` (not threaded through every `assign`/`release` call) because the pool
already reads `sessionCap` fresh every tick and can set the mode once per tick before calling
assign/release.

### Invariants to hold

1. `SessionNumberAllocator.assign(origin:sessionId:)` must always return the SAME number for a
   sessionId that is still live (never observed to change while the session has not been
   `release`d), and must return the LOWEST currently-free number for that origin (from
   `freeNumbers`, else the monotonic high-water mark) when assigning a new sessionId.
2. `FloatingPetWindowPool.sessionNumber(forWindowKey:)` and the assign/release call sites inside
   `update(snapshot:)` must return/act on `nil`/no-op for any window key that is not session-keyed
   (a plain origin with no colon, or the literal `"combined"`) — session numbers must never be
   allocated or reported for those windows.
3. Under an Unlimited origin (`sessionCap[origin] == 0`), `release` must never insert into
   `freeNumbers` — numbering must stay strictly monotonic with no reuse, and `assign` must never
   return a previously-freed number for that origin.

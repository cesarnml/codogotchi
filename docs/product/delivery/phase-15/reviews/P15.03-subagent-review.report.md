**Actionable findings**

**F1 — Equal-timestamp tie-break divergence breaks Invariant 1 for same-origin sessions**

File: `apps/menubar/Sources/RenderKeyResolver.swift` (the `consider()` closure) and `apps/menubar/Sources/StateJsonReader.swift` (`readPerPlatformDirectoryImpl`).

What is wrong: when two sessions of the same origin share an identical `updated_at` string and session-pets is off, `resolveRenderKeys` picks the winner by whichever key Swift's Dictionary iterates first (implementation-defined, not entries-listing order). `readPerPlatformDirectoryImpl` picks the winner by which entry appears first in the `listing.entries` array (also implementation-defined, but it is the entries-iteration order, not Dictionary iteration order). Both readers share the same `sharedListing`, so their `entries` order is identical — but the per-session path re-inserts into a Dictionary before `resolveRenderKeys` iterates it, introducing a second independent non-determinism. For equal-timestamp slices, the two readers can select different `StateSnapshot` values, violating Invariant 1.

Clause: finding-discipline clause 2 (demonstrable correctness gap). Practical impact: near-zero — two sessions writing the identical millisecond-precision ISO 8601 timestamp is extremely unlikely in production.

Recommendation: add a secondary deterministic tie-break inside `consider()` — e.g., when `candidate == existingDate`, prefer the lexicographically lesser `origin:sessionId` (or `sessionId`). This makes the collapse deterministic and ensures byte-identity with `readPerPlatformDirectoryImpl` under all inputs, not just the common distinct-timestamp case. Alternatively, add a test that asserts which session wins for equal timestamps to document the tie-break contract explicitly even if the current behavior is left as-is.

**Advisory Observations**

- **A1 — `.tmp-` filter could silently skip a session whose `session_id` contains the literal substring `.tmp-`.** An agent that generates a session ID like `mytmp-abc` would write `claude_code:mytmp-abc.json` and the `contains(".tmp-")` check would skip it. This is the same filter used across all three readers (`readDirectoryImpl`, `readPerPlatformDirectoryImpl`, `readPerSessionDirectoryImpl`), so the risk is not new to P15.03 — but the per-session path makes it more reachable because session IDs are agent-generated strings rather than fixed origin enum values. The ticket does not name this as a skip rule in Invariant 2. Outside the three finding-discipline clauses (session ID format is not specified as guaranteed `.tmp-`-free, so this is a latent interface assumption, not a code break).

- **A2 — Legacy gate/context applied to all sessions when session-pets is ON and exactly one origin is active.** With `sessionPetsEnabled["claude_code"] = true` and three active sessions, `resolveRenderedPlatforms` sees `distinctOrigins == {"claude_code"}` → `singleOrigin == "claude_code"` → the flat `gate.json`/`delivery-context.json` (written by a pre-Phase-17 hook with no per-origin context) is applied as the fallback gate for all three session windows. Pre-P15.03, one window per origin meant the fallback was applied to one window. This is a behavior change from the prior semantics, but it only activates when session-pets is ON, which requires explicit configuration. It is acknowledged under "Deferred" in the Rationale and will be fully reconciled in P15.04. Surfacing here for P15.04 author awareness.

- **A3 — `testAllDefaultCollapseEqualsPerOriginMap` does not cover filename-origin / content-origin divergence.** The per-session reader is filename-authoritative; the per-origin reader is content-authoritative. For a slice whose `source_event.origin` differs from its filename prefix, the two readers produce different map keys. The test fixture uses `writeSlice` which always writes matching content and filename origins, so this case is not covered. This is the intentional design documented in the Rationale's "Alternative considered" section, but a dedicated negative-case test (asserting that per-session and per-origin keys deliberately diverge when origins mismatch) would make the design decision explicit and prevent a future refactor from accidentally "fixing" the divergence in the wrong direction.

- **A4 — One-tick torn render set during Settings writes.** The shared listing is captured before `customizationReader()` is called in the same tick. A user toggling session-pets ON in Settings between those two operations gets one tick where old session data is collapsed using the new customization. Self-corrects on the next poll. No data loss or persisted inconsistency. Inherent to non-atomic multi-file polling at 1 Hz.

**P8.08 Developer tab — read-only observability**

Outcome:

### Invariants to hold

1. `last5Transitions` must return at most 5 entries, all non-heartbeat, in file order (oldest first among the last 5); a missing or empty log must return `[]` without throwing.
2. `schemaVersionMismatch` must be `false` when state.json schema == `EXPECTED_STATE_SCHEMA_VERSION` and `true` when they differ; it must not throw or crash on an absent state.json.

### Attack surfaces to probe

1. **`readLastNTransitions` — malformed NDJSON line handling** — if one line is malformed JSON, the loop calls `continue`; probe whether malformed lines in the middle of the file silently skip real transition entries that follow them.
2. **`schemaVersionMismatch` when state.json is absent** — `stateSchemaVersion` returns 0 when unreadable; `schemaVersionMismatch` then checks `sv != 0 && sv != rv`, so it returns `false` (not `true`) for absent files. Probe whether this is the documented contract and whether the test covers it.
3. **`gateJsonPretty` when path is configured but file is absent** — returns the string "(gate.json absent or unreadable)" rather than `nil`; this is a non-nil return for an absent file. Probe whether the Developer tab UI correctly distinguishes "configured but absent" from "not configured (nil)".
4. **`hooksPresentSummary` platform filter** — filters to `installableInPhase == true` only. Probe whether `antigravity` (not installable in phase 8) is correctly excluded from the summary.
5. **`lastSeenSourceOrigin` — searches `last5Transitions` only** — uses `last5Transitions.last { $0.sourceOrigin != nil }`, which only scans the last 5 log entries. If the last 5 are all heartbeats (which are filtered out), and the most recent non-heartbeat transition with a sourceOrigin was further back in the log, the explainer returns nil. Probe whether this is an expected limitation or a gap.

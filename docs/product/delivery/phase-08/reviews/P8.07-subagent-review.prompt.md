### Ticket scope

**P8.07 Pet tab — enumerate/select/import + Maew default**

Outcome:
- The Pet tab lists pets from three sources: Codex built-in (`~/.codex/pets/`), custom (`~/.codogotchi/pets/`), and the bundled Maew.
- Selecting a Codex/custom pet imports it via `PetImportHelper` (overwrite-with-rollback-backup) into `~/.codogotchi/pets/<id>/`.
- Maew is the default: with no Codex pet imported and no prior selection, Maew is the active pet out of the box.
- The active selection persists (to config.json via `PetConfig.write`) and drives the renderer; switching pets calls `MenubarApp.reloadActivePet()` to push new pets into all renderers live.

Rationale notes:
- `PetTabViewModel` enumerates 3 sources, deduped by ID; always inserts bundled Maew.
- `selectPet(id:)` writes to configURL atomically; fires `onActivePetChanged`.
- `importPet(id:)` delegates to `PetImportHelper.importPet(id:)` (no re-implementation).
- `PetConfig.write(petName:to:)` is a new method: creates parent dirs, writes `{"pet": name}` atomically.
- `MenubarRenderer`, `FloatingPetScene`, `FloatingPetPanelController`, `LivePollingDriver`: `codexPet`/`codogotchiPet` changed from `let` to `var`; `replacePets`/`replaceCodogotchiPet` methods added.
- `MenubarApp.reloadActivePet()`: reconstructs both loaders using `PetConfig.resolvedPetName()` (which now returns the new ID), pushes to all renderers.

### Invariants to hold

1. `PetTabViewModel.allPetIds()` must always include `DEFAULT_PET_NAME` ("maew"), regardless of whether Codex or canonical roots exist.
2. `PetTabViewModel.selectPet(id:)` must persist the selected ID to `configURL` and fire `onActivePetChanged`; it must be a no-op (no write, no callback) when `id` already equals `activePetId`.
3. `MenubarApp.reloadActivePet()` must push new pet instances to all three renderer surfaces (menubar renderer, floating pet scene, live polling driver); a `CodexPet()` load failure must not crash but should log.

### Attack surfaces to probe

1. **`PetTabViewModel.allPetIds()` — Codex root absent** — when `codexPetsRoot` does not exist, `contentsOfDirectory` throws; the guard-let in `allPetIds` swallows the error with `continue`. Confirm that the fallback still includes `DEFAULT_PET_NAME` and does not skip the second root.
2. **`PetConfig.write` atomicity** — uses `Data.write(to:options:.atomic)`. If `configURL`'s parent doesn't exist, `createDirectory` creates it. Probe whether a concurrent write (two rapid `selectPet` calls) can leave `config.json` partially written or with no `pet` key.
3. **`MenubarApp.reloadActivePet()` — race between Settings close and renderer tear-down** — the closure captures `[weak self]`; if `MenubarApp` is deallocated between the pet-selection event and the closure firing, `reloadActivePet()` silently no-ops. Probe whether this leaves the renderer in a state with stale pets (old CodogotchiPet paths) after the user restarts.
4. **`PetImportHelper` delegation in `importPet`** — `PetTabViewModel.importPet(id:)` creates a new `PetImportHelper` with its stored root URLs. Verify the roots are the same ones enumerated by `allPetIds()` — if a different `canonicalPetsRoot` were passed to each, an import could land in a different directory than the one the list shows.
5. **`replacePets` on `FloatingPetPanelController` when scene is nil** — `scene?.replacePets(...)` is an optional call. If the floating panel has never been shown, `scene` is nil and the call is silently skipped; `codexPet`/`codogotchiPet` are still updated on `self`. Probe whether the *next* `show(frame:)` call picks up the new pets (it constructs a new `FloatingPetScene` using `self.codexPet`/`self.codogotchiPet`, which are now updated — so it should be fine).

### Ticket scope

**Outcome:**
- `app-state.json` gains an `installedHookVersion` field; `APP_STATE_SCHEMA_VERSION` bumps 1→2 with an idempotent migration that defaults the field to `nil` for existing files.
- On Install / Update hooks, the app records the **bundled** hook version (reported by the bundled `codogotchi --version`/generation token) into `installedHookVersion`.
- On launch, when hooks are installed **and** the bundled version differs from `installedHookVersion`, the app shows a **persistent, non-blocking banner** ("Hooks are out of date — Update") that runs the install-API update and clears on success.
- When versions match (or no hooks installed), no banner.
- The app never silently rewrites agent config dirs — the banner requires a user click.

**Rationale notes:**
- `LockstepPolicy` guards on bundledVersion == "unknown" — no banner if the binary can't be queried, preventing a false-positive nag on broken installs. `recordInstalledHookVersion` skips the write for the same reason.
- Version token comes from `AboutViewModel.bundledHookVersion()` which runs `codogotchi --version`; returns "unknown" on failure.

### Attack surfaces to probe

1. `AppStateStore.load` — schema version gate: the condition `payload.schemaVersion <= APP_STATE_SCHEMA_VERSION` now accepts 1 and 2. Probe whether a v1 file still passes this gate after the constant was bumped to 2, and whether a v3 file still falls back to the default.
2. `AppStatePayload` optional decode — `installedHookVersion` is `let` (not `var`) and optional. Probe whether Swift's Codable decoder correctly defaults it to `nil` when the key is absent in a v1 JSON payload, or whether the decoder throws and falls through to the fallback state.
3. `recordInstalledHookVersion` background-thread write: this method is called on `DispatchQueue.global(qos: .userInitiated)` after a successful hook action. It calls `appStateLoader()` to re-read the current state, then `appStateSaver()` to write back. Probe whether concurrent hook actions (two rapid taps) could produce a lost-update: both reads complete before either write, and the second write clobbers the first without carrying forward any state the first write set.
4. `GeneralTabViewModel.needsBannerUpdate` — `rows` dependency: the property checks `rows.contains { $0.installed }`. Before `applySnapshot` is called, `rows` is empty. Probe whether `needsBannerUpdate` incorrectly returns `false` on first display (no rows yet) even when `installedHookVersion` is nil and hooks are actually installed — i.e., whether the banner is suppressed until the first snapshot arrives.
5. `UpdateBannerView.onUpdate` — banner button wiring: the button calls `onUpdate?()` which is set to `onUpdateHooks`. Probe whether `onUpdateHooks` also calls `recordInstalledHookVersion`, closing the loop so the banner hides after the update completes.
6. `SettingsWindowController.openWindow` — `installedHookVersion` load: the controller loads `installedHookVersion = savedState.installedHookVersion` before calling `applySnapshot` or `refresh`. Probe whether the banner is correctly shown on re-open of the settings window when a version mismatch persists (i.e., `openWindow` runs again after the window was closed).

### Diff context

Key logic changes:

   ```swift
   static func needsUpdate(hooksInstalled: Bool, bundledVersion: String, installedVersion: String?) -> Bool {
       guard hooksInstalled else { return false }
       guard bundledVersion != "unknown" else { return false }
       return bundledVersion != installedVersion
   }
   ```

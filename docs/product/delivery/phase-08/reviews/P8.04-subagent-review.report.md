**Actionable findings**

- `apps/menubar/Sources/SettingsWindowController.swift:156-166`, `175-185`, `194-204` — each action refreshes the `GeneralTabViewModel` after the subprocess returns, but the refreshed model is only applied on the success branch. This breaks the ticket outcome clause that the per-platform status is “refreshed after each action”: a non-zero exit that still leaves changed on-disk state, or that fails after a partial rewrite, will show a fresh inline error but stale status rows. Fix: call `applyViewModel(vm)` on the main thread after every `vm.refresh()`, then layer success or error feedback on top of the refreshed rows.
- `apps/menubar/Sources/GeneralTabViewModel.swift:65-72` with the `HooksStatusSnapshot` contract in `packages/cli/src/hooks.ts:690-723` — `diagnosticsJSON()` does not preserve the `hooks status --json` shape. Swift’s synthesized `Encodable` drops nil optionals, so `last_event_at` disappears instead of being present as `null`, and when `lastSnapshot` is nil the entire `hooksStatus` object is omitted. That violates the ticket’s “status JSON (+ versions)”/“same shape” contract and will hand support a payload that does not match CLI output. Fix: build `hooksStatus` explicitly from `HooksStatusSnapshot`, writing all contract keys including `last_event_at: NSNull()` when absent, and emit an explicit empty `hooksStatus` object when no snapshot is available.

### Attack surfaces to probe

1. **`resolveHalfHearts` — NaN/Infinity/invalid ISO inputs**: `Date.parse` returns `NaN` for malformed ISO strings. If `lastActivityAt` is a non-null but malformed string (e.g. `"not-a-date"`), `elapsedHours` becomes `NaN`, and `Math.floor(NaN / 8) = NaN`, so `afterDecay = Math.max(0, n - NaN) = NaN`, and `Math.min(6, NaN + healGain) = NaN` — a number outside `[0,6]` violating invariant 2.
2. **`resolveHalfHearts` — `currentHalfHearts` out-of-range input**: What if a caller passes `currentHalfHearts = -1` or `currentHalfHearts = 7`? The function does not clamp the input, so `Math.max(0, 7 - 0) = 7`, `Math.min(6, 7 + 0) = 6` — that's fine for the cap case. For negative input: `Math.max(0, -1 - 0) = 0`, `Math.min(6, 0 + 0) = 0` — also fine. But verify there is no escape path for combined extreme inputs (negative current + large heal gain).
3. **`resolveHalfHearts` — simultaneous idle + active clamping order**: When `lastActivityAt` is set and both `idleDecay > currentHalfHearts` and `healGain > 0`, verify the function applies decay floor-first (`afterDecay = max(0, current - decay)`) then adds heal, not the combined formula `clamp(current - decay + heal, 0, 6)`. These differ: ghost + 1 active hour with the combined formula yields `max(0, min(6, 0 - 6 + 1)) = 0` (wrong), while decay-first gives `min(6, max(0, 0-6) + 1) = 1` (correct per spec).
4. **`index.ts` — export collision**: `hearts.ts` exports `MAX_HALF_HEARTS`, `HALF_HEART_DECAY_HOURS`, `ACTIVE_MINUTES_PER_HALF_HEART`, `HalfHeartsInput`, `resolveHalfHearts`. Check whether any of these names collide with existing exports from `health.ts`, `level.ts`, `loot.ts`, `xp.ts`, or the sources barrel — a collision in a re-export barrel causes a silent type error at the consumer.
5. **`health.ts` — dormant model untouched**: Confirm the diff applies zero changes to `health.ts`, `health.test.ts`, or the dormant `ProfileHealth`/`HealthConfig`/`tickHealth`/`hpBucket` API.

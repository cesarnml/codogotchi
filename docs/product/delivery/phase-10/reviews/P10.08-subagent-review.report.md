**Actionable findings**

**Finding 1 — features type coercion strips rpg_enabled on non-dict features value**
File: `apps/menubar/Sources/PetConfig.swift:64`
What is wrong: When `obj["features"]` is present but not `[String: Any]` (e.g., `null`, array), the merge produces `features: {"rpg_hud_enabled": <value>}`. The `rpg_enabled` key — required by the CLI's `router.ts` to gate RPG-only code paths — is stripped. A subsequent `codogotchi hooks install` or router evaluation silently demotes the config from RPG to Lite mode. Applies to both `write(rpgHUDEnabled:to:)` (new code) and `write(petName:to:)` (existing code, same pattern).
Invariant: Invariant 2 (merge, not clobber).
Fix recommendation: Replace the silent `?? [:]` with an explicit guard that re-seeds `rpg_enabled` when the cast fails, for example:
```swift
var features = (obj["features"] as? [String: Any]) ?? ["rpg_enabled": false]
```
This matches the fallback seeding already done in the `else` branch (line 60–62) and ensures `rpg_enabled` is never silently lost when the features block is malformed.

**Finding 2 — silent write failure causes persistent data loss on disk-full or permission error**
File: `apps/menubar/Sources/RPGTabViewModel.swift:32`
What is wrong: `try? PetConfig.write(rpgHUDEnabled: enabled, to: configURL)` suppresses all errors. On disk-full or permission-denied the in-memory `rpgHUDEnabled` reflects the user's toggle while the config file is unchanged. The user sees the HUD respond (live read via `MenubarApp.swift:293` re-reads config on poll), but on next launch the config overrides the in-memory value and the toggle state reverts silently.
Finding discipline: Spec-permits-real-bug — the ticket spec does not require error surfacing, but the consequence is a user-visible data-loss regression (toggle change silently not persisted).
Fix recommendation: Surface write errors to the UI (e.g., post an `NSAlert` or set an error label on the RPG tab) rather than swallowing them. At minimum, revert `rpgHUDEnabled` in-memory if the write fails so the UI stays consistent with what will survive a relaunch:
```swift
func setRPGHUDEnabled(_ enabled: Bool) {
    rpgHUDEnabled = enabled
    do {
        try PetConfig.write(rpgHUDEnabled: enabled, to: configURL)
    } catch {
        rpgHUDEnabled = !enabled  // revert so in-memory matches on-disk
    }
}
```

### Attack surfaces to probe

1. **`levelForXp` binary-search boundary at index 0** — when `xp === 0`, `safeXp` returns 0, the `xp >= LEVEL_T` guard is false, binary search starts with `lo=0 hi=99`. The loop invariant requires `LEVEL_THRESHOLDS[mid] <= xp` to be checked. Since `LEVEL_THRESHOLDS[0] === 0`, the condition `0 <= 0` is true. Verify that `lo` ends at 0 and `levelForXp` returns 1, not 0. Out-by-one on the return `lo + 1` would give level 0.

2. **`safeXp` treats `0` as falsy — possible off-by-one** — `safeXp` returns `n > 0 ? n : 0`. For `totalXp === 0`, this returns 0 (correct). For `totalXp === -0` (negative zero in JS), `(-0) > 0` is false, so returns 0 (also correct). Probe whether `Infinity` or very large finite values break the binary search bounds or cause `mid` computation overflow.

3. **`levelProgress` at level 100 returning stale `into` value** — when `xp >= LEVEL_T`, `levelForXp` returns 100. Then `levelProgress` computes `into: xp - lo > 0 ? xp - lo : 0`. If called with `xp === LEVEL_T` exactly, `lo = LEVEL_THRESHOLDS[99] = LEVEL_T`, so `xp - lo === 0`, `into` should be 0. Probe that `into` is 0 when xp exactly equals LEVEL_T, not a negative value.

4. **`levelProgress` `span` computation for level 100** — the level-100 branch computes `span: lo - prev` where `lo = LEVEL_THRESHOLDS[99]` and `prev = LEVEL_THRESHOLDS[98]`. This span is the width of the last level interval — but `fraction` is hardcoded to 1, so `span` is unused by consumers. Still, probe that `span` is positive (not zero or negative) to avoid confusing callers who inspect it.

5. **Rounding collision in `LEVEL_THRESHOLDS` — two adjacent entries could be equal after `Math.round`** — for small `i` values at the bottom of the curve, the increment between consecutive thresholds could be so small that rounding makes them equal, breaking the strict monotonicity invariant. The test sweeps all 100 entries, but probe whether there is any pair `LEVEL_THRESHOLDS[i] === LEVEL_THRESHOLDS[i+1]` analytically. With T=68e9 and exponent 2.5, the minimum increment at i=1 is approximately `T × (1/99)^2.5 - 0 ≈ 68e9 × 1e-5 ≈ 700,000` — large enough. Verify this reasoning is sound.

6. **`export *` from `level.ts` name collision with existing `xp.ts` exports** — adding `export * from "./level"` to `index.ts` could cause a name collision if any export from `level.ts` has the same name as an export from `xp.ts`, `health.ts`, `loot.ts`, or the source modules. TypeScript would emit an error only if both modules export the same name. Probe whether `LEVEL_T`, `LEVEL_COUNT`, `LEVEL_EXPONENT`, `LEVEL_THRESHOLDS`, `levelForXp`, `levelProgress`, or `LevelProgress` collide with any existing export names.

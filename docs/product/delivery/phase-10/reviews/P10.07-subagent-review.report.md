**Actionable findings**

**Finding 1** — `FloatingPetPanel.swift`, `mouseExited` (lines 1537–1552) / `handlePointerEvent` (lines 1888–1910).

What is wrong: `mouseExited` sets `pointerInsideFrame = false` for the bounds tracking area before calling `handlePointerEvent`. Inside `handlePointerEvent`, `let wasInBounds = pointerInsideFrame` reads the already-updated `false`. When the mouse exits, `inBounds` is also `false`. The delta check `inBounds != wasInBounds` evaluates `false != false = false`, so `onHoverChange?(false)` is never called. `isHoveringPet` in `FloatingPetPanelController` remains `true`, and `repositionAndShowHUD()` is never triggered with the hide path after mouse exit. The HUD does not auto-hide on mouse leave, breaking the ticket's stated invariant.

Which clause: Clause 2 — demonstrable correctness gap. The hover-leave branch of the stated behavior (HUD hides on leave) does not execute.

Concrete fix recommendation: Remove the `pointerInsideFrame = false` pre-assignment from `mouseExited`. Let `handlePointerEvent` own all reads and writes of `pointerInsideFrame`. When `mouseExited` fires, `handlePointerEvent` will compute `inBounds = false` from `mouseLocationOutsideOfEventStream`, read the correct old `pointerInsideFrame = true`, detect the `true → false` delta, and fire `onHoverChange?(false)`. The change is three lines:

```swift
// In mouseExited — remove this block:
// if kind == Self.trackingKindBounds || kind == nil {
//     pointerInsideFrame = false
// }
```

`handlePointerEvent` already assigns `pointerInsideFrame = inBounds` internally, so removing the pre-assignment causes no other regression.

**Advisory Observations**

The `onFlash` closure on `rpgHUDViewModel` is reassigned on every `applyRPGState` call (every polling tick). The closure is semantically identical each time (same capture list, same body), so this is a minor allocation churn at 1Hz but not a correctness issue.

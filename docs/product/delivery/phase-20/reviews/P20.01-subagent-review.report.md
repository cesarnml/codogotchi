**Invariant 2 (lifecycle edge set/clear rules):** Holds for all six integration-tested paths (prompt submit, mid-turn tool, errored, standby+attention, idle, session birth). `mergeStickyStamps` early-return order is sound: `idle` runs before `prompt_submit`/`session_start`, so idle cannot leave turn clocks; `errored` runs after those branches and does not clear `turn_ended_at` or reset an existing `errored_since`, which matches the stated edge list (only `idle` and turn-start edges clear turn clocks). `runHook` always supplies `hasAttention: true` for `standby` via `buildAttention`, so `turn_ended_at` is set on real standby writes. `waiting_for_input` carries attention but correctly does not set `turn_ended_at` (spec limits that stamp to `standby`+attention).

## Surface results

**1. `mergeStickyStamps` early-return order:** Probed via code trace and existing tests. `idle` clears `prompt_started_at`, `errored_since`, `turn_ended_at` and returns before `prompt_submit`/`session_start` or `errored` branches — no stuck turn clocks after idle. `errored` after `standby` preserves `turn_ended_at` and does not reset `errored_since`; consistent with invariant 2 as written.

**2. `readPriorStickyStamps` loose parse:** Probed. All failure paths (`readFile` error, `JSON.parse` error, non-object) return `{}` with no logging or write abort. On the next **successful** write, `mergeStickyStamps` treats missing `session_started_at` as first-create and stamps `nowIso`, silently resetting session-birth and dropping any other prior stamps that were on disk but unreadable. Invalid datetime strings in prior are passed through and cause `sliceEntrySchema.parse` to throw in `writeSliceAtomic`, which `runHookFromStdin` swallows — activity updates freeze with last-good on-disk state (fail-closed on write, not on read).

**3. Stamp merge vs `isStaleSliceWrite`:** Probed. Stale writes are dropped entirely in `writeSliceAtomic` when `existingMs > incomingMs`; on-disk activity and stamps stay aligned. Prior stamps are read at lock acquisition before merge; a dropped stale write does not partially update stamps. Existing test `rejects an out-of-order slice write that would clobber a newer terminal state` covers activity; stamp consistency follows the same guard.

**4. `standby` without attention vs `waiting_for_input`:** Probed. `buildAttention` always returns an attention object for `standby` and `waiting_for_input`, but `mergeStickyStamps` only sets `turn_ended_at` for `standby && hasAttention`. `waiting_for_input` correctly omits `turn_ended_at`. No path in `runHook` produces `standby` without attention.

## Actionable findings

**Spec-permits-real-bug — corrupt prior slice silently resets sticky clocks on successful write.** `readPriorStickyStamps` is documented as “best-effort” and returns `{}` on any read/parse failure without aborting the write. `mergeStickyStamps` then sets `session_started_at = nowIso` when that key is absent (lines 1279–1280), and other prior stamps (`prompt_started_at`, `turn_ended_at`, `errored_since`) are likewise dropped. A subsequent write succeeds and overwrites the slice with reset clocks. This breaks invariant 1 (mid-turn preservation after a prior good `prompt_submit`) and invariant 2 (`session_started_at` set once / preserved through idle) whenever the on-disk slice becomes unreadable (corrupt JSON, truncated file, etc.). The ticket outcome does not specify fail-closed behavior on corrupt prior, and the code comment explicitly chooses tolerance over validation — that design permits the unsafe production behavior (silent clock reset / Sessions birth time wrong) rather than blocking the write.

## Advisory Observations

- **v9 unstamped migration fabricates `session_started_at`:** For an existing v9 slice with no stamp keys, the first v10 write sets `session_started_at` to the migration write time. Literal ticket wording (“first write … sets `session_started_at`”) permits this, but it is not the true session birth; P20.03 plans to omit Started when the field is missing rather than infer it.
- **Invalid prior datetime strings block all subsequent writes silently:** Loose read accepts any `typeof value === "string"`; Zod rejects on output; `runHookFromStdin` catches and exits 0. Pet activity can freeze with no user-visible error.
- **`mergeStickyStamps` is exported but has no direct unit tests** — edge ordering (e.g. `errored` after `standby` retaining `turn_ended_at`) is only covered by code inspection and partial integration coverage.
- **No test for v9→v10 stamp preservation** or corrupt-prior recovery despite being named attack surfaces.
- **Installer lockstep is rebuild-dependent:** Refreshing hook registrations without rebuilding the embedded `codogotchi-hook` binary leaves old v9 writer behavior until the app/binary is rebuilt.
- **Swift menubar still at `EXPECTED_STATE_SCHEMA_VERSION = 9`:** Deferred per ticket; slice directory reader tolerates v10 files for activity/attention but ignores stamp fields until P20.02+.
- **`docs/contracts/animation-state-vocabulary.md` still describes v9 slice shape** without sticky fields — P20.04 scope.
- **`globalAggregate` / `sliceToStateJson` strip stamp fields** from aggregated `StateJsonV1`; consistent with current consumers but worth noting for any code path aggregating before reading stamps.

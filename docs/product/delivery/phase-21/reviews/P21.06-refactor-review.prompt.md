### Ticket scope

P21.06 Multi-issue Origin close

`parseOriginIssueNumber` (`tools/delivery/planning.ts`) is superseded by a multi-line-aware
parser (`parseOriginIssueNumbers`) that returns every `Origin issue: #<N>` line from the
`## Epic` section, in document order, deduplicated; single-line plans parse identically to
today. Delivery state (`tools/delivery/types.ts`) carries the full list
(`originIssueNumbers`); existing single-issue state files load without migration. `open-pr`
for the phase's final ticket only appends one `- Closes #<N>` bullet per origin issue to
the PR body; earlier tickets' PRs get none (unchanged semantics). Near-miss lines are still
rejected — the parser stays strict. `docs/template/stubs/product-plan.template.md`,
`docs/template/stubs/implementation-plan.template.md`,
`docs/template/delivery/delivery-orchestrator.md`, and
`.agents/skills/preflight/SKILL.md` document the multi-line form.

Rationale (from the ticket doc): renamed `parseOriginIssueNumber` to
`parseOriginIssueNumbers` outright rather than keeping the old name as a wrapper — only
one caller (`state.ts`'s `loadPlanContext`), so renaming cost one call-site edit and kept
the parser's contract unambiguous. `normalizeDeliveryStateFromPersisted` gained a small
legacy-read helper that wraps a persisted single `originIssueNumber` into a one-element
array at load time. A deprecated single-value accessor (`originIssueNumbers[0]`) was
considered and rejected — only two real consumers, both cheaper to update directly.

## Rationale (implementation notes, post-GREEN — appended by primary agent)

- `CustomizationJsonReader` kept as a standalone type (store's input, not folded in) — smaller diff, isolated decode/clamp tests.
- Publication API: closure-based `subscribe(_:) -> Token` / `unsubscribe(_:)` on `CustomizationStore`, NOT Combine, NOT NotificationCenter. All mutating store methods (`merge`, `setMode`, `setCombinedMinimalistEnabled`, `setMinimalistBadgeScale`) accept `notify: Bool = true` so the Panel Size drag can write every tick but publish only on the final tick — reproducing the pre-refactor `isFinal`-gated notification post.
- Publication is **per-`CustomizationStore`-instance** — only subscribers registered on the SAME instance that performed the write are notified. Production code (`MenubarApp`) shares one `customizationStore` instance across the right-click handlers and `SettingsWindowController`'s `CustomizationTabViewModel`/`GeneralTabViewModel` so a right-click write reaches an open Settings tab.
- `CustomizationTabViewModel` guards its own store subscription with an `isApplyingOwnWrite` flag so its own writes (already applied to its `private(set)` properties from the store's returned snapshot) do not also fire `onExternalChange` on itself — reproducing the pre-refactor asymmetry where the Settings tab's own edits never posted the old notification.
- `GeneralTabViewModel` does NOT subscribe to the store at all (matches pre-refactor: it never observed `.customizationDidChangeExternally` either — only `CustomizationTabView` did).
- `SettingsWindowController`'s DI: `customizationTabViewModel: CustomizationTabViewModel = CustomizationTabViewModel()` became `customizationStore: CustomizationStore = CustomizationStore()` + optional `customizationTabViewModel: CustomizationTabViewModel? = nil` override (same pattern for `generalViewModel`). No existing test or call site injects the VM override directly today.
- No pre-existing "last-writer-wins" bug found in the flagged interleaving: `ConfigFileWriter.merge` already re-read the file fresh on every call before this ticket.

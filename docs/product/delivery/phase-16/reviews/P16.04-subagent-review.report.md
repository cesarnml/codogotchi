**Actionable findings**

- `apps/menubar/Sources/Pool/RenderKeyResolver.swift:113` — when session pets are disabled, the new implementation assigns `renderKey = .origin(origin)`. For an input such as `"combined:s1"` under default/own customization, this yields `.origin("combined")`, which is distinct from `.combined`. The base implementation assigned the raw origin string `"combined"`, which collided with and therefore followed the shared-combined window path. This breaks invariant 3 and is a demonstrated correctness regression for the existing `source_event.origin == "combined"` wire value. Fix by canonicalizing raw-origin render keys through the legacy parse mapping at this boundary, so raw `"combined"` becomes `.combined`, and add resolver-to-pool regression tests for a `"combined:<session>"` input with session pets both off and on. The fix should also explicitly decide whether session-pets-on behavior must preserve the legacy `"combined:<session>"` session key.
